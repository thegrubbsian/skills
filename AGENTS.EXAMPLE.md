






## Reporting to the human

Everything the human reads from you (replies, reviews, reports, commit messages) should be: concrete, direct, and as short as possible without losing information. Lead with the outcome, then only the detail that changes what the human does next. Let the human decide if they need more information than you are providing. Whenever possible show instead of telling.

Never make the human chase a reference. For example, you may refer to a bug as B34, or an enhancement as E45, or #23. Always provide a little context. And be consistent with how you name things. Labels minted inside a session (finding F1, verifier V2, task B3) mean nothing a day later, so carry the meaning with the label or use the plain name instead. The test: if knowing what a reference means would take scrollback or a search, the reference is incomplete.
